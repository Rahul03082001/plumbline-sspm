About Plumbline

A small SaaS Security Posture Management (SSPM) service. A plumb line checks whether a wall is truly straight, not just whether it looks straight.

Live vs simulated

One live integration: a GitHub organization, scanned through the REST API with a read-only, fine-grained token. The connector can only send GET requests.

One simulated tenant (github:acme-demo): demo data in GitHub's own response format, which changes between scans (v1 → v2 → v2 → v1) so you can watch drift happen. It runs through the exact same client and normalizer as the live scan. It is not a real integration.

How to read the results

  • Pass / fail / unknown. If any field a rule needs can't be read (missing permission, field not returned), the result is unknown, never pass.
  • Score + coverage, always together. Score starts at 100 and loses 15/8/3/1 per critical/high/medium/low failure, counting only checks we could assess. Below 60% coverage we show no score at all.
  • Not comparable. If a failing check became unknown, or coverage fell more than 5 points, a higher score may just mean "we see less". We flag it and leave it out of the trend line.
  • Unverifiable (amber): failing the last time we could read it, unreadable now. Not counted as resolved.
  • Missing is not removed. An asset only counts as removed after a complete listing. Until then it is carried forward as unknown.

This is a single-instance demo

It runs on Cloud Run with --max-instances=1; the job queue and the SQLite database live inside that one instance. Data resets when the instance restarts, and the simulated tenant is re-seeded at startup. max-instances is a scaling limit, not a lock: a real multi-tenant product would use a shared database and a durable task queue.
